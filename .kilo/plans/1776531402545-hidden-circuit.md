# Plan: Generic Battery SKU Builder (multi-prefix support)

## Context

The current `ecolitio_build_variation_sku()` in `battery-variation-helpers.php` hard-codes the `eco-bame-` prefix. New battery product types (`eco-tapa`, `eco-basa`) follow the **same voltage + amperage attribute structure** but need a different SKU prefix. More types may be added in the future.

The agreed approach is to **derive the prefix from the parent product's own SKU** — no extra post-meta field, no hard-coded map. The parent product SKU already carries the battery family name (e.g. `eco-bame`, `eco-tapa`, `eco-basa`), so variations should be named `{parent-sku}-{voltage}-{amperage}`.

---

## Design Decisions

| Question | Decision |
|---|---|
| Same attributes for all battery types? | Yes — all use `voltios` + `amperios` |
| Different available options per type? | Yes — each product has its own set of voltages/amperages |
| Where does the prefix come from? | Extracted from the parent WooCommerce product's SKU |
| Backward compatibility with `eco-bame`? | Yes — `ecolitio_build_variation_sku` stays as an alias |

---

## Changes

### 1. `battery-variation-helpers.php` — new generic builder

**Add** `ecolitio_build_variation_sku_for_product( $product_id, $voltage, $amperage )`:

```php
function ecolitio_build_variation_sku_for_product( $product_id, $voltage, $amperage ) {
    $parent = wc_get_product( $product_id );
    $prefix = $parent ? $parent->get_sku() : 'eco-battery';

    $voltage  = strtolower( str_replace( ' ', '', $voltage ) );
    $amperage = strtolower( str_replace( ' ', '', $amperage ) );

    return $prefix . '-' . $voltage . '-' . $amperage;
}
```

**Update** `ecolitio_build_variation_sku()` to accept an optional prefix (defaults to `eco-bame`) — keeps old call sites working without changes:

```php
function ecolitio_build_variation_sku( $voltage, $amperage, $prefix = 'eco-bame' ) {
    $voltage  = strtolower( str_replace( ' ', '', $voltage ) );
    $amperage = strtolower( str_replace( ' ', '', $amperage ) );
    return $prefix . '-' . $voltage . '-' . $amperage;
}
```

**Update** `ecolitio_get_variation_id_for_specs( $product_id, $voltage, $amperage )` to use the new product-aware builder:

```php
function ecolitio_get_variation_id_for_specs( $product_id, $voltage, $amperage ) {
    $sku = ecolitio_build_variation_sku_for_product( $product_id, $voltage, $amperage );
    return ecolitio_get_variation_id_by_sku( $sku );
}
```

Update the function docblock on line 17 to reflect the generic SKU format:
- Before: `eco-bame-{voltage}-{amperage}`
- After: `{parent-product-sku}-{voltage}-{amperage}`

### 2. `ajax.php` — update diagnostic log (line 585–587)

The diagnostic `error_log` call still uses the old two-argument `ecolitio_build_variation_sku`. Update it to use the product-aware version so logs show the correct SKU:

```php
$built_sku = function_exists( 'ecolitio_build_variation_sku_for_product' )
    ? ecolitio_build_variation_sku_for_product( $product_id, $form_data['voltage'], $form_data['amperage'] )
    : 'helper_not_loaded';
```

## SKU convention going forward

Parent product SKU → variation SKU pattern:

| Parent SKU | Example variation SKU |
|---|---|
| `eco-bame` | `eco-bame-24v-4,8ah` |
| `eco-tapa` | `eco-tapa-36v-9,6ah` |
| `eco-basa` | `eco-basa-48v-19,2ah` |

This means when creating new battery products in WooCommerce, the parent product must have its SKU set to the battery family prefix. Variation SKUs then follow the pattern `{parent-sku}-{voltage}-{amperage}`.
